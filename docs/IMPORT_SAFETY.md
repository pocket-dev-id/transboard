# 取り込み設定の整理・段階実装

## 第1段階: データ保持と再実行

- 予定CSVの全件置換は、全ファイル・全行の日時検証成功後に実行する。
  ファイル確認・読み込み・日時検証の失敗や空CSVでは既存予定と原本を保持する。
- CSVの原本処理はDB保存成功後に行う。処理中に内容が変わった原本は移動・削除しない。
- 患者CSVは読み込み開始前の設定と、保存直前の設定を比較する。
  ODBCも取得開始前の設定を保存待ちキューの中で再確認する。
- 自動走査は内容と設定の処理記録で重複更新を抑制する。手動取り込みは再実行する。
  通常の処理記録は直近512件に制限する。予定CSVは一括処理の記録も持つ。
- 予定の原本移動失敗は、重複判定用キャッシュとは別の永続記録で管理する。
  この記録は全フィード合計5000原本までとし、超過時には置換前に中止する。
  新しい予定CSVが来た場合、以前に保存済みの原本は後処理だけを再試行する。
  「そのまま残す」方式ではフォルダ全体を一つのスナップショットとして扱う。
- アーカイブ整理は親機で起動時と24時間ごとに行う。通常CSVだけを対象とし、
  ディレクトリやシンボリックリンク、その他のファイルには触れない。
  保存期間はアーカイブ時から数え、0は無期限。共有フォルダは長い期間を優先する。
  従来の予定CSV設定に保存期間が無い場合は無期限として引き継ぐ。
- 処理記録は暗号化されたDB内の内部フィールドに保存し、子機向けテーブルAPIには公開しない。

## 続く段階

1. ODBC接続情報の構造化と接続文字列の安全な生成、詳細設定との関係整理。
2. SMBの旧認証設定をサーバー共通設定へ移行。競合する旧設定は自動で上書きせず表示する。
3. 成功・失敗・原本処理失敗の履歴を親機へ統一する。
4. 全件・差分設定の二重保持を解消し、病床番号の正規化・索引を共通化する。
5. 移送中の患者ID変更を確認対象として扱う処理と画面を整える。
6. 復旧用監査ログとバックアップを管理画面から選択して整理できるようにする。

通話・ビデオ・チャット・音声通知、NFC・患者ID自動設定は対象外。

## 確認

`npm run check` に全件検証、保存期間、再処理、設定変更、513ファイルの部分移動失敗の
回帰テストを含める。Windows実機ではUNC共有、ODBC実ドライバー、再起動を伴う確認が必要。
