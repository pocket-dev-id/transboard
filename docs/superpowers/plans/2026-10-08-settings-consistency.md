# 設定・取込処理の整理

> **For agentic workers:** Use superpowers:executing-plans task-by-task.

**Goal:** 設定の正本と処理の完了判定を統一し、不整合を減らす。

**Architecture:** 端末役割ファイルを正本とし、旧DBとブラウザ設定は互換キャッシュにする。取込は親機mainで変換・検証・保存・原本整理を完結する。既存のキーとデータを移行する。

**Tech Stack:** Electron、Node.js、ブラウザJavaScript。

**Spec:** 2026-10-08の棚卸しレビューと利用者の実装指示。通話・ビデオ・チャット・音声通知、NFC・患者ID自動設定は対象外。

## Global Constraints
- Windows 11、Node 22、追加依存なし。
- 既存設定とデータを保持し、旧形式を読み込む。
- 既存の競合検出・監査・バックアップを維持する。

## Review Focus
- ディスク容量不足時は保存先を切り替えない。
- 旧ブラウザキャッシュで親機に昇格しない。
- 部分CSVで対象外病棟を空床にしない。
- ODBC取得成功だけで保存成功と表示しない。
- 管理配布端末が自己更新を実行しない。

## Tasks
1. 端末設定・保存先移行: 正本読込、接続保存IPC、コピー検証後の切替。実ファイルと障害注入テスト。
2. 接続先変更: 共通保存処理、病棟再確認と初回同期、未完了状態。ブラウザVMテスト。
3. 患者取込: 親機変換・一括保存、CSV/ODBC共通経路、全件・差分と病棟範囲。取込回帰テスト。
4. 実行管理: 親機取込の直列化、共通スケジュール、再接続。重複実行テスト。
5. 同期: 共通再試行方針、停止・再開管理。仮想タイマーテスト。
6. 状態: ブラウザとmainの共通定義、フロープリセット。全状態・役割の照合テスト。
7. 管理設定: ODBC詳細設定の分離、SMBサーバー単位資格情報、保持容量の表示、管理配布の更新抑止。
8. npm run check、Windows CI、全体レビュー、PR作成。

各タスクは回帰テストの失敗を確認してから実装し、チェック成功後にコミットする。
