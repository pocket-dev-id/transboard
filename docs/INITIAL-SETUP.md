# 初期設定

親機は稼働モード・連携・端末設定・確認の4段階、子機は接続・端末設定・確認の3段階です。子機は親機の起動とAPIトークン認証を確認してから担当病棟を取得します。完了時にも再確認するため、接続不能の場合は完了せず設定画面に留まります。

担当病棟・端末表示名・画面役割・倍率・フォントは端末ごとの設定です。検査室端末には担当病棟の選択は不要です。ICカード・連携・在室管理は親機の共有設定で、子機の初期設定から書き換えません。

保存失敗時は完了扱いにせず、成功した項目は保存されたまま再適用できます。完了状態はローカルの `cfg_wizard_completed` と `terminal_role.json` の `setupCompleted` で確認します。従来の設定済み親機は共有の `wizard_completed` を互換用に利用しますが、新しい子機には適用しません。

## 管理配布

`provisioning.json` の取り込み成功は設定の保存を意味し、利用準備完了を意味しません。初回起動で投入値を表示し、担当病棟・端末名と、子機の場合は接続・認証を確認して完了します。

途中で役割・トークン・DBの保存に失敗した場合は失敗を返し、役割ファイルに未完了状態とトークンを含まないエラー理由を保存します。次回起動でも初期設定を案内します。書き込み不能時のエラーはその起動中にも通知します。

平文トークンを残さないため、入力ファイルは成功・失敗とも削除します。失敗した端末は容量・書き込み権限を修正してウィザードから再入力するか、新しい `provisioning.json` を再投入してください。既に保存できた病棟・端末名などは省略しても維持されます。トークンはOSの保護機能で暗号化保存し、エラー理由や監査ログには含めません。

## 手動確認

- 新規子機でトークン未入力・誤入力・親機停止を試し、完了できないことを確認。
- 子機で親機の病棟一覧から担当を選択し、表示名・倍率・フォントを変更。親機の共有設定が変わらず、再起動後に子機だけへ反映されることを確認。
- 保存先を書き込み不可にして設定を適用し、完了画面にならないことを確認。権限を戻して再適用。
- 配布ファイルを投入し、初期値が表示されること、未完了表示から再設定できることを確認。
- 設定済み親機を更新し、互換用の完了判定で既存運用が維持されることを確認。

## 新規DBのマスター

新規DBには架空の病棟・病床・検査室・職員・介助区分・検査種別を登録しません。初期設定で病棟端末を選んだ場合は、入力した最初の病棟を登録してから設定を完了します。病床、検査室、職員、検査種別などは実際の運用に合わせて設定画面から登録してください。既存DBの登録内容は自動削除・変更しません。

## 子機の初回同期

子機は接続・認証後、病棟、病床、検査室、検査種別、介助区分、職員、共有設定を親機から取得できた場合に初期設定を完了します。一部の取得が失敗した場合は未完了のまま再適用できます。再起動時の通信失敗では保存した担当病棟を消さず、接続回復後に同じ病棟へ戻ります。

## 接続設定と共通設定の保存

設定画面の「接続設定を保存」はこの端末の親機・子機、接続先、トークンを保存します。子機は保存前に接続・認証を確認し、失敗時は以前の接続設定を保持します。通話・患者登録の共通設定は親機の専用ボタンで保存します。接続先の変更だけでは共通設定を書き換えません。
