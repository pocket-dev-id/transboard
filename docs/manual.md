## 1. 起動と初期設定

### 初回起動時

初回起動時に**初期機能設定ウィザード**が自動的に表示されます。

| ステップ | 設定内容 |
|----------|----------|
| 1. 稼働モード | 親機（スタンドアロン/サーバー）または子機（クライアント）を選択 |
| 2. 連携設定 | 子機の場合、親機のIPアドレスを入力 |
| 3. 表示・管理 | 表示倍率・パスコードの設定 |
| 4. 確認と完了 | 設定内容を確認して完了 |

> **ヒント:** すでに設定済みの場合は「スキップ」で閉じられます。

### パスコード

設定画面はパスコードで保護されています。

- **初期値:** `0000`
- 初回起動後、必ず変更してください（設定 → 詳細設定 → パスコード変更）

## 2. 病棟ダッシュボード


メイン画面です。病棟内すべての患者の移送状況をリアルタイムで確認できます。

### ステータスサマリー（画面上部）

| 項目 | 説明 |
|------|------|
| 出棟中 | 現在、検査室へ移送中または検査中の患者数 |
| 付き添い中 | 看護師が付き添い対応中の患者数 |
| 迎え要 | 検査終了・帰棟の迎えが必要な患者数 |
| 15分以内 | 検査終了予定まで15分以内の患者数 |
| 遅延 | 予定時刻を超過している患者数 |

### 病床マップ

各病床カードには以下の情報が表示されます。

- **病床番号** （例: 701）
- **移送状態バッジ** （移動中 / 検査室到着 / 検査中 / あと10分 / 迎え要 / 帰棟済）
- **検査室・検査種別** （例: CT室 → CT）
- **残り時間・経過時間**
- **担当看護師名**

#### フィルタリング

「絞り込み」ボタンで表示する状態を絞り込めます：

- **すべて** — 全病床を表示
- **出棟中** — 移送中・検査中の病床のみ
- **お迎え要** — 迎え待ちの病床のみ
- **空床** — 空床のみ
- **不在** — 患者不在の病床のみ

### 優先対応一覧（画面右）

迎えが必要な患者を優先度順に表示します。時刻超過の場合は赤字で警告表示されます。

### タイムライン（画面下部）

当日の移送履歴を時系列バーで確認できます。「タイムラインを開く」ボタンで詳細ビューに移動します。

## 3. 検査室ビュー

検査室側のPC専用画面です。ナビゲーションバーの「**検査室**」タブから開きます。

### 主な操作

| ボタン | 動作 |
|--------|------|
| 到着 | 患者が検査室に到着したことを記録（状態 → 検査中） |
| あと10分 | 検査終了10分前を通知（状態 → あと10分） |
| 検査終了 | 検査完了・帰棟準備（状態 → 迎え要） |

> **検査室ビューは子機からでも操作可能です。** 検査室に子機タブレットを置いてご利用ください。

---

## 4. タイムライン

当日の全移送イベントを時系列で確認できます。ナビゲーションバーの「**タイムライン**」タブから開きます。

- 横軸が時刻、縦軸が病床番号
- バーの色で移送状態を視覚的に識別
- 過去のイベントにマウスを合わせると詳細情報を表示
- CSVで取り込んだスケジュールのうち、実際の予定時刻が無い(時刻列が空)ものは
  時間軸には表示せず、画面下部の「時間未定のスケジュール」にチップとして
  一覧表示される

---

## 5. 履歴・監査ログ

過去の移送履歴と状態変更の監査ログを確認できます。ナビゲーションバーの「**履歴**」タブから開きます。

### イベント一覧（左パネル）

患者ごとの移送イベント一覧。検査室・状態・担当者・使用備品が記録されます。

### 状態変更ログ（中央パネル）

いつ・誰が・どの患者の状態を変更したかの詳細ログ。

### 通話履歴（右パネル）

院内通話（WebRTC）の発着信履歴。

### CSVエクスポート

画面右上の「CSV出力」ボタンで履歴データをCSV形式でエクスポートできます。

## 6. システム設定

ナビゲーションバーの「**設定**」タブから開きます（パスコード入力が必要です）。

### 設定タブ一覧

| タブ | 説明 |
|------|------|
| 病棟マスタ | 病棟名・内線番号の登録・編集 |

| マップ配置 | 病床マップの表示レイアウト設定 |
| 検査室マスタ | 検査室名・内線番号の登録 |
| 検査種別 | 検査名・標準所要時間の設定 |
| スタッフ | 担当スタッフの登録 |
| 取り込み設定 | CSV自動取込フォルダ・カラムマッピング設定 |
| 通知音設定 | 状態変化時の通知音設定 |

| 共有・ネット | 親機/子機モード・IPアドレス設定 |

## 7. 移送状態の操作手順

### 病棟側（移送開始）

1. 病床マップで対象の病床カードをクリック
2. 検査室・検査種別・担当者・使用備品を入力
3. 「移送を開始」をクリック
4. 状態が「移動中」になり、移送開始時刻が記録されます

> その患者にCSV取り込みのスケジュールが紐づいている場合、病床詳細画面が
> 右側に拡張され、取り込み済みスケジュール(時刻・検査名・取り込み元)の
> 一覧が表示されます。

### 検査室側（到着〜終了）

1. 検査室ビューで対象患者の「到着」をクリック → 状態が「検査中」に変わります
2. 検査終了10分前に「あと10分」をクリック → 病棟側に通知
3. 検査終了後「検査終了」をクリック → 状態が「迎え要」に変わり、病棟に通知音が鳴ります

### 病棟側（迎え・帰棟）

1. 優先対応一覧または病床マップで「迎え要」患者を確認
2. 迎えに向かい、帰棟後に病床カードから「帰棟済」をクリック

## 8. 複数端末での運用

### 親機（メインPC）の設定

1. 設定 → 共有・ネット → **「親機として動作する」** を選択
2. 表示されたIPアドレスをメモ（例: `192.168.1.10`）
3. Windowsファイアウォールで**ポート 3005** を許可

### 子機（サブPC・タブレット）の設定

1. TransBoardをインストールして起動
2. 設定 → 共有・ネット → **「子機として動作する」** を選択
3. 親機のIPアドレス（例: `192.168.1.10`）を入力して保存

> 親機・子機は同一ネットワーク（院内LAN）内に接続されている必要があります。

### 多数の端末へ一括で導入する場合（システム管理者向け）

上記の手動設定は端末ごとの作業になるため、台数が多い環境では
**初期設定ファイル（`provisioning.json`）による一括投入**が利用できます。

各端末の `%APPDATA%\transboard\` に次の内容のファイルを配置しておくと、
**次回起動時に自動で取り込まれ、ウィザードの手入力が不要**になります。

```json
{
  "version": 1,
  "shareMode": "client",
  "parentIp": "192.168.1.10",
  "terminalRole": "ward",
  "wardId": "ward-1",
  "apiToken": "（親機の設定画面で確認できるAPIトークン）",
  "managed": true,
  "expiresAt": 1767225600000
}
```

| 項目 | 必須 | 説明 |
|---|---|---|
| `version` | ○ | 現在は `1` 固定 |
| `shareMode` | ○ | `parent`（親機）/ `client`（子機） |
| `parentIp` | 子機のみ○ | 接続先の親機IPアドレス |
| `terminalRole` | | `ward`（病棟端末）/ `exam`（検査室端末）。既定は `ward` |
| `wardId` | | 既定で表示する病棟のID。**まだ一度も病棟を選んでいない端末でのみ**採用され、利用者が選び直した病棟を上書きすることはありません |
| `apiToken` | 子機は実質必須 | 親機との通信に使うトークン |
| `managed` | | `true` にすると「管理配布された端末」として記録され、更新時の案内が「管理者へ連絡してください」に変わります |
| `expiresAt` | | 有効期限（Unixミリ秒）。過ぎたファイルは取り込まれずに破棄されます |

**セキュリティ上の重要な注意:**

- このファイルには**APIトークンが平文で含まれます**。取り込み後、TransBoardは
  成否に関わらず**このファイルを必ず削除**します（トークンは以後、OSの
  資格情報保護機能で暗号化して保存されます）。
- 配置元の共有フォルダにも平文のまま残さないでください。配布後は削除してください。
- 万一配り損ねた場合に備え、`expiresAt` を設定して有効期限を短くしておくことを推奨します。
- 取り込み結果は監査ログに記録されます（トークンの値そのものは記録されません）。

### 端末間の連絡（通話・アナウンス・チャット）

画面右下の電話ボタンを押すと、連絡パネルが開きます。病棟・検査室の一覧から相手を選んで連絡できます。

| 操作 | 方法 |
|---|---|
| 音声・ビデオ通話／アナウンス送信 | 相手の行をクリックして「連絡方法の選択」を開く |
| チャット | 相手の行の右端にある吹き出しボタンをクリック |

**チャット画面の見方**

チャット画面には、その相手とのやりとりが時系列で並びます。

- 右側（青）… 自分が送ったメッセージ
- 左側（グレー）… 相手から届いたメッセージ

アナウンスは送信すると相手の端末で自動的に読み上げられます。「いつ・何を伝えたか」の履歴は
チャット画面ではなく、**送信先の病棟・検査室の通知履歴パネル**（拡声器アイコン・オレンジ枠）に、
病床の状態変更通知と時系列で混ざって表示されます。自分が送った分はチャット画面・通知履歴の
どちらにも表示されません（届いた側にだけ記録が残ります）。

> チャットとアナウンス履歴は親機のデータベースに保存されるため、アプリを再起動しても消えません。
> 受信時に起動していなかった端末でも、後から開けば内容を確認できます。
> 音声・ビデオ通話を無効に設定している場合でも、チャットは利用できます。

### 親機を別のパソコンに移す場合

親機PCの故障・機種変更などで役割を別のPCに移す場合の手順は
[docs/MIGRATION.md](MIGRATION.md) を参照してください。

## 9. バージョンアップ手順

TransBoardはper-userインストール（`%LOCALAPPDATA%\Programs\`配下）のため、**更新に管理者権限は不要**です。

### リリースの作成（開発者向け）

1. `npm version patch`（または`minor`/`major`）でバージョンを上げてコミットし、タグ`vX.Y.Z`をpush
2. GitHub Actionsが自動でインストーラ（.exe）・`latest.yml`・`.blockmap`をビルドし、GitHub Releasesに添付

> `npm run dist`/`npm run pack`はローカルでの動作確認用で、バージョン番号は変更しない。バージョンを上げるのは上記の`npm version`コマンドを明示的に実行したときだけなので、ビルドを試すたびに`package.json`が汚れて`git pull`が妨げられることはない。

### 親機の更新と子機への配信

1. GitHub Releasesから **インストーラ（.exe）と `latest.yml` の両方** をダウンロード
   （インターネット非接続の親機へは、別PCでダウンロードしUSBメモリ等で持ち込み）
2. 親機の 設定 → 共有・ネット → **「子機への更新配信」→「更新ファイルを取込」** で2ファイルを選択
   - 取込時にsha512整合性を自動検証します。破損ファイルや組み合わせ違いは拒否されます
3. 取込が完了すると、親機自身にも「更新あり」の通知（ヘッダーのバージョンバッジ）が表示されるので、**まず親機を更新**
4. 各子機は次回起動時または24時間ごとの自動チェックで更新通知を受け取り、バージョンバッジのクリック→「更新する」でワンクリック更新
   （設定画面の「今すぐ更新を確認」で即時チェックも可能）

> **更新順序は必ず「親機 → 子機」**。設定 → 共有・ネットの「接続機器一覧」で各子機のバージョンを確認でき、親機と異なる端末には ⚠ が表示されます。

### 更新の安全対策

- ダウンロードしたインストーラは`latest.yml`のsha512と照合され、一致しない場合はインストールされません
- 更新の直前にデータベースが`db.json.before_update`として自動退避されます
- 更新は通知のみで、インストールは常にユーザーの確認操作で開始されます（業務中の強制更新はありません）

### ロールバック（1つ前のバージョンに戻す）

1. 親機の「子機への更新配信」→「1つ前の配信に戻す」で配信を旧バージョンに戻す（新しい端末が増えるのを止める）
2. すでに更新済みの端末を戻す場合は、その端末で旧バージョンのインストーラを手動実行

### 旧バージョン（Program Files版）からの移行

v1.1.x以前をProgram Files配下にインストールしている場合のみ、一度だけ手動での入れ替えが必要です:
旧版をアンインストール → 新版インストーラを実行（以後はper-userインストールとなり管理者権限不要）。
データベースは`%APPDATA%\transboard\`にあるためアンインストールしても保持されます。

該当する端末で「更新する」を押すと、「このインストールは旧バージョン（Program Files配下）のため自動更新できません」というメッセージが表示されます（自動更新は行われず、ダウンロードも行われません）。これが表示された場合は上記の手動での入れ替えが必要という合図です。

### 管理配布（マシン単位インストール）した端末の更新

システム管理者がマシン単位（Program Files配下）で一括配布した端末は、
**アプリ自身の自動更新は行われません**（インストール先の書き換えに管理者権限が
必要なため）。この場合の更新は管理者が一括で配布します。

該当端末で「更新する」を押すと「この端末はシステム管理者によって配布・管理されています」
というメッセージが表示されます。利用者側でアンインストール・再インストールを
**行わないでください**（管理外の状態になり、以後の一括更新から外れてしまいます）。

> マシン単位のインストーラは `npm run dist:per-machine` でビルドします。
> この成果物は**親機の更新配信フォルダへ置かないでください**。通常の子機
> （ユーザー単位インストール）が取得してしまい、インストール形態が混在します。

## トラブルシューティング

| 症状 | 対処法 |
|------|--------|
| 子機が親機に接続できない | 親機のIPアドレスが正しいか確認。ファイアウォールでポート3005を許可 |
| 子機が**急に**接続できなくなった（親機の画面は正常） | 親機で`netstat -ano \| findstr :3005`を実行し、何も表示されなければ共有サーバーが停止している。原因は稼働モード設定の破損（旧バージョンの不具合で、子機の設定保存が親機のモードを上書きすることがあった）。修正版に更新して**親機を起動し直すと自動修復ダイアログが表示される**ので、指示に従い再起動する |
| CSV取込が動作しない | 監視フォルダのパスとカラムマッピングを確認。文字コードはUTF-8/Shift-JIS自動判定 |
| 通知音が鳴らない | 設定 → 通知音設定 で音量・有効/無効を確認 |
| 設定画面が開けない | パスコード初期値は `0000`。変更済みの場合は設定したパスコードを入力 |
| データが消えた | バックアップから復元：設定 → データ管理 → バックアップから復元 |
