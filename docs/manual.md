## 1. 起動と初期設定

### 初回起動時

初回起動時に**初期機能設定ウィザード**が自動的に表示されます。

| ステップ | 設定内容 |
|----------|----------|
| 1. 稼働モード | **単独運用**（この1台だけで完結）／**親機**（子機と共有）／**子機**（クライアント）を選択 |
| 2. 連携設定 | 子機の場合、親機のIPアドレスを入力 |
| 3. 表示・管理 | 表示倍率・パスコードの設定 |
| 4. 確認と完了 | 設定内容を確認して完了 |

> **単独運用モード:** 子機を使わず1台だけで運用する場合に選びます。検査室タブ・病棟間通話・接続端末表示など多端末前提のUIが隠れ、病棟画面だけで全工程を操作できます。あとから子機を追加する場合は設定でOFFにできます。

> **ヒント:** すでに設定済みの場合は「スキップ」で閉じられます。

### パスコード

設定画面はパスコードで保護されています。

- **初期値:** `0000`
- 初回起動後、必ず変更してください（設定 → 詳細設定 → パスコード変更）
- パスコードを5回連続で間違えると60秒間ロックされます

## 2. 病棟ダッシュボード


メイン画面です。病棟内すべての患者の移送状況をリアルタイムで確認できます。

### ステータスサマリー（画面上部）

| 項目 | 説明 |
|------|------|
| 出棟中 | 現在、検査室へ移送中または検査中の患者数 |
| 付き添い中 | 実際に付き添い移動中のスタッフがいる患者数（検査中などで病棟へ戻り手離れしている分は「（待機N）」で補足） |
| 迎え要 | 検査終了・帰棟の迎えが必要な患者数（発生時はカードが点滅） |
| 15分以内 | 検査終了予定まで15分以内の患者数 |
| 遅延 | 予定時刻を超過している患者数 |

### 病床マップ

各病床カードには以下の情報が表示されます。

- **病床番号** （例: 701）
- **移送状態バッジ** （登録済 / 移動中 / 検査中 / あと10分 / 迎え要 / 帰棟済）
- **検査室・検査種別** （例: CT室 → CT）
- **残り時間・経過時間**（迎え目安までの経過をバーで表示）
- **担当看護師名**（付き添い中／病棟待機を区別して表示）
- **患者名・患者ID**（「患者名を表示」がONのとき。OFFではマスク表示）

#### 操作・表示切替（フィルタバー）

- **絞り込みボタン** — 表示する状態を絞り込み（すべて／出棟中／お迎え要／空床／不在）
- **患者名を表示** — 病床カードや優先対応一覧に患者名を表示（既定は非表示・マスク）
- **全病棟表示** — 全病棟の病床マップを病棟ごとにまとめて横断表示
- **ズーム（−/100%/＋）** — 病床マップの拡大・縮小（Ctrl+ホイールでも操作可）
- **備考表示モード** — 備考をアイコンのみ／本文表示／非表示で切替
- **右クリック** — 病床カードを右クリックしてステータスをその場で変更

### 優先対応一覧（画面右）

迎えが必要な患者を優先度順に、コンパクトな1行表示で一覧します。時刻超過の場合は赤字で警告表示されます。「患者名を表示」がONのときは患者名も表示します。付き添いスタッフは、実際に移動中は「付き添い中: 氏名」、検査中などで病棟待機中は「担当: 氏名（病棟待機）」と区別して表示されます。

### スタッフ稼働状況（画面右）

登録スタッフの稼働を「付き添い中／病棟待機／空き」のチップで一覧表示します。右上のプルダウンで **全員 / 稼働中のみ**（付き添い中・病棟待機のみ）を切り替えられます。

### タイムライン（画面下部）

当日の移送履歴を時系列バーで確認できます。「タイムラインを開く」ボタンで詳細ビューに移動します。

## 3. 検査室ビュー

検査室側のPC専用画面です。ナビゲーションバーの「**検査室**」タブから開きます。

### 主な操作

| ボタン | 動作 |
|--------|------|
| 到着 | 患者が検査室に到着したことを記録（状態 → 検査中） |
| あと10分 | 検査終了10分前を通知（状態 → あと10分） |
| 検査終了 | 検査完了・帰棟準備（状態 → 迎え要） |

> **検査室ビューは子機からでも操作可能です。** 検査室に子機タブレットを置いてご利用ください。
> 単独運用モードでは検査室タブは表示されません（病棟画面ですべて操作します）。

---

## 4. タイムライン

当日の全移送イベントを時系列で確認できます。ナビゲーションバーの「**タイムライン**」タブから開きます。

- 横軸が時刻、縦軸が病床番号
- バーの色で移送状態を視覚的に識別
- 過去のイベントにマウスを合わせると詳細情報を表示

---

## 5. 履歴・監査ログ

過去の移送履歴と状態変更の監査ログを確認できます。ナビゲーションバーの「**履歴**」タブから開きます。

### イベント一覧（左パネル）

患者ごとの移送イベント一覧。検査室・状態・担当者・使用備品が記録されます。

### 状態変更ログ（中央パネル）

いつ・誰が・どの患者の状態を変更したかの詳細ログ。

### 通話履歴（右パネル）

院内通話（WebRTC）の発着信履歴。

### 検査時間実績

帰棟済みの移送から、移動時間・検査所要時間・迎え待ち時間・病棟を離れていた総時間を**自動集計**します。

- 期間（直近7日/30日/90日/全期間）と集計単位（検査種別ごと／検査室ごと）を切り替え可能
- 実績平均が標準時間と大きく異なる検査種別には、**標準時間への反映提案**が表示されます（適用にはパスコードが必要）
- 「明細CSV」ボタンで1件ごとの実績を書き出せます
- 集計対象は**表示中の病棟**の帰棟済み移送のみです

### CSVエクスポート

画面右上の「CSV出力」ボタンで履歴データをCSV形式でエクスポートできます。

## 6. システム設定

ナビゲーションバーの「**設定**」タブから開きます（パスコード入力が必要です）。タブはカテゴリ（**全体共通 / 親機機能 / 端末・接続**）ごとにまとまり、画面幅に応じて折り返して表示されます。

### 設定タブ一覧

| タブ | 説明 |
|------|------|
| 病棟マスタ | 病棟名・内線番号の登録・編集 |
| 病床マスタ | 病床番号・種別（一般/隔離/ICU）の登録 |
| 病床タイプ | 病床の分類設定 |
| マップ配置 | 病床マップの表示レイアウト設定（複数選択・一括操作・病室単位のグルーピング対応） |
| 検査室マスタ | 検査室名・内線番号の登録 |
| 検査種別 | 検査名・標準所要時間の設定 |
| スタッフ | 担当スタッフの登録 |
| アナウンス定型文 | 院内放送用テキストの登録 |
| ステータスカスタマイズ | 各ステータスの表示ラベル・色・非表示（使わないステータスのスキップ）の設定 |
| 取り込み設定 | CSV自動取込フォルダ・カラムマッピング設定（親機機能） |
| スケジュール取り込み | 手術・検査スケジュールCSVの取込設定（親機機能） |
| 通知音設定 | 状態変化時の通知音設定（端末ごと） |
| 共有・ネットワーク設定 | 親機/子機/単独運用モード・IPアドレス・更新配信（端末ごと） |

## 7. 移送状態の操作手順

### 病棟側（出棟登録）

1. 病床マップで対象の病床カードをクリック
2. 「出棟登録」ボタンをクリック
3. 検査室・検査種別・担当者・使用備品を入力
4. 「登録」をクリック → 状態が「出棟登録済」に変わります
   - 続けて確認ダイアログが出ます。**「移動中にする」**を選ぶと即「移動中」へ、**「出棟登録のまま」**を選ぶと登録のみ保持します（どちらを選んでも出棟登録は保存されます）

### 移送開始

1. 病床カードをクリック → 「移動中」ボタンをクリック
2. 患者の移送を開始します

### 検査室側（到着〜終了）

1. 検査室ビューで対象患者の「到着」をクリック → 状態が「検査中」に変わります
2. 検査終了10分前に「あと10分」をクリック → 病棟側に通知
3. 検査終了後「検査終了」をクリック → 状態が「迎え要」に変わり、病棟に通知音が鳴ります

> 単独運用モードや、検査室ステータスを「非表示」に設定している運用では、検査室ビューを使わず病棟画面の操作だけで移送を進められます。

### 病棟側（迎え・帰棟）

1. 優先対応一覧または病床マップで「迎え要」患者を確認
2. 迎えに向かい、帰棟後に病床カードから「帰棟済」をクリック

## 8. 複数端末での運用

### 単独運用モード（1台完結）

子機を使わず親機1台だけで運用する場合に使います。設定 → 共有・ネットワーク設定 →「単独運用モード」をON（または初回ウィザードで「単独運用」を選択）。検査室タブ・病棟間通話・接続端末表示など多端末前提のUIが隠れ、病棟画面だけで全工程を操作できます。あとから子機を追加する場合はOFFにしてください。

### 親機（メインPC）の設定

1. 設定 → 共有・ネットワーク設定 → **「親機として動作する」** を選択
2. 表示されたIPアドレスをメモ（例: `192.168.1.10`）
3. Windowsファイアウォールで**ポート 3005** を許可

### 子機（サブPC・タブレット）の設定

1. TransBoardをインストールして起動
2. 設定 → 共有・ネットワーク設定 → **「子機として動作する」** を選択
3. 親機のIPアドレス（例: `192.168.1.10`）を入力して保存

> 親機・子機は同一ネットワーク（院内LAN）内に接続されている必要があります。

## 9. 表示・テーマ設定

見やすさに合わせて表示を調整できます（設定 → 表示に関する項目）。

- **テーマ** — 既定（フラットUI）のほか、ダーク・ハイコントラスト・色覚サポートなど複数のテーマから選択可能
- **表示サイズ** — 病床カード等の大きさを大／中／小で切替
- **文字スタイル** — UDフォント・太字など読みやすさ向けの設定
- **患者名の表示/マスク** — 病床カード・優先対応一覧での患者名表示のON/OFF

## 10. バージョンアップ手順

TransBoardはper-userインストール（`%LOCALAPPDATA%\Programs\`配下）のため、**更新に管理者権限は不要**です。

### リリースの作成（開発者向け）

1. `npm version patch`（または`minor`/`major`）でバージョンを上げてコミットし、タグ`vX.Y.Z`をpush
2. GitHub Actionsが自動でインストーラ（.exe）・`latest.yml`・`.blockmap`をビルドし、GitHub Releasesに添付

> `npm run dist`/`npm run pack`はローカルでの動作確認用で、バージョン番号は変更しない。バージョンを上げるのは上記の`npm version`コマンドを明示的に実行したときだけなので、ビルドを試すたびに`package.json`が汚れて`git pull`が妨げられることはない。

### 親機の更新と子機への配信

1. GitHub Releasesから **インストーラ（.exe）と `latest.yml` の両方** をダウンロード
   （インターネット非接続の親機へは、別PCでダウンロードしUSBメモリ等で持ち込み）
2. 親機の 設定 → 共有・ネットワーク設定 → **「子機への更新配信」→「更新ファイルを取込」** で2ファイルを選択
   - 取込時にsha512整合性を自動検証します。破損ファイルや組み合わせ違いは拒否されます
3. 取込が完了すると、親機自身にも「更新あり」の通知（ヘッダーのバージョンバッジ）が表示されるので、**まず親機を更新**
4. 各子機は次回起動時または24時間ごとの自動チェックで更新通知を受け取り、バージョンバッジのクリック→「更新する」でワンクリック更新
   （設定画面の「今すぐ更新を確認」で即時チェックも可能）

> **更新順序は必ず「親機 → 子機」**。設定 → 共有・ネットワーク設定の「接続機器一覧」で各子機のバージョンを確認でき、親機と異なる端末には ⚠ が表示されます。

### 更新の安全対策

- ダウンロードしたインストーラは`latest.yml`のsha512と照合され、一致しない場合はインストールされません
- 更新の直前にデータベースが`transboard-db.json.before_update`として自動退避されます
- 更新は通知のみで、インストールは常にユーザーの確認操作で開始されます（業務中の強制更新はありません）

### ロールバック（1つ前のバージョンに戻す）

1. 親機の「子機への更新配信」→「1つ前の配信に戻す」で配信を旧バージョンに戻す（新しい端末が増えるのを止める）
2. すでに更新済みの端末を戻す場合は、その端末で旧バージョンのインストーラを手動実行

### 旧バージョン（Program Files版）からの移行

v1.1.x以前をProgram Files配下にインストールしている場合のみ、一度だけ手動での入れ替えが必要です:
旧版をアンインストール → 新版インストーラを実行（以後はper-userインストールとなり管理者権限不要）。
データベースは`%APPDATA%\TransBoard\`にあるためアンインストールしても保持されます。

## トラブルシューティング

| 症状 | 対処法 |
|------|--------|
| 子機が親機に接続できない | 親機のIPアドレスが正しいか確認。ファイアウォールでポート3005を許可 |
| 子機が**急に**接続できなくなった（親機の画面は正常） | 親機で`netstat -ano \| findstr :3005`を実行し、何も表示されなければ共有サーバーが停止している。原因は稼働モード設定の破損（旧バージョンの不具合で、子機の設定保存が親機のモードを上書きすることがあった）。修正版に更新して**親機を起動し直すと自動修復ダイアログが表示される**ので、指示に従い再起動する |
| ビデオ通話でカメラが映らない | 画質を下げると自動フォールバックで対応解像度を探して復帰します（v1.2.0で改善）。他アプリがカメラを使用していないかも確認 |
| CSV取込が動作しない | 監視フォルダのパスとカラムマッピングを確認。文字コードはUTF-8/Shift-JIS自動判定 |
| 通知音が鳴らない | 設定 → 通知音設定 で音量・有効/無効を確認 |
| 設定画面が開けない | パスコード初期値は `0000`。変更済みの場合は設定したパスコードを入力（5回間違えると60秒ロック） |
| データが消えた | バックアップから復元：設定 → データ管理 → バックアップから復元 |
