# 親機を別のパソコンに移す手順

親機PCの故障・機種変更などで、親機の役割を別のパソコンに移す場合の手順です。
単なるバージョンアップは対象外です（[manual.md 9. バージョンアップ手順](manual.md)を参照）。

---

## 全体の流れ

```
[旧親機]                              [新親機]
  1. バックアップを取る  ──(ファイル)──▶  2. TransBoardをインストール
                                         3. バックアップを復元
                                         4. 親機モードに設定して保存・再起動
  5. 子機として動作するよう切替
     （または電源を切ったままにする）

[各子機]
  6. 設定 → 共有・ネット で親機のIPアドレスを新PCのものに変更 → 再起動
```

**重要:** 手順3（復元）と手順4（親機モードの設定）は**両方**必要です。
バックアップには親機/子機の設定（`share_mode`）も含まれていますが、それだけでは
端末の役割が確定しません（後述「なぜ手順4が必須なのか」）。

---

## 手順

### 1. 旧親機でバックアップを取る

1. 旧親機の 設定 → 保守 → 「データベースのバックアップ」
2. **暗号化バックアップ（パスワード方式）を選択**（推奨・下記「バックアップ方式の選び方」参照）
3. パスワードを設定して保存し、USBメモリ等で新親機に運ぶ

### 2. 新親機にインストール

新PCにTransBoardをインストールします。この時点ではまだ何も設定しません
（初期設定ウィザードが起動しても、いったんキャンセルまたは後述の手順4まで進めて構いません）。

### 3. 新親機でバックアップを復元

1. 設定 → 保守 → 「データベースの復元」
2. 手順1で作成したバックアップファイルを選択し、パスワードを入力
3. 復元が完了すると、旧親機の病棟・病床・スタッフ等のマスタと、
   （暗号化バックアップの場合は）APIトークンも引き継がれます

### 4. 新親機を親機モードに設定する（復元後、必ず実施）

1. 設定 → 共有・ネット → **「親機として動作する」** を選択して保存
2. アプリを再起動
3. 表示されたIPアドレスをメモ（子機の設定で使用）
4. Windowsファイアウォールで**ポート 3005** を許可

#### なぜ手順4が必須なのか

端末の役割（親機/子機）は、共有DBの設定値だけでなく、**その端末のローカルファイル**
（`terminal_role.json`）にも保存されています。これは、子機が誤ってDB同期中に
親機の役割設定を書き換えてしまう事故を防ぐための仕組みです。

そのため、バックアップに含まれる`share_mode`（親機/子機の別）は**復元した直後の
1回だけ**有効になり、手順4を行わずに再起動すると、新PCが「まだ親機に設定されて
いない端末」と判定されて元の役割に戻ってしまいます。復元後は必ず設定画面から
明示的に親機モードを選択・保存してください。

### 5. 旧親機を無効化する

新親機の準備ができたら、旧親機を**電源オフのままにする**か、
設定 → 共有・ネット → 「子機として動作する」に切り替えてください。

TransBoardには「他の端末が親機を名乗っていないか」を自動検知する仕組みが
ありません。旧親機を親機モードのまま稼働させ続けると、子機ごとに接続先が
分かれてデータベースが分岐する可能性があります。**新旧どちらが親機か、
LAN内で同時に2台が親機を名乗らないよう運用で徹底してください。**

### 6. 各子機の接続先を新親機に変更する

子機ごとに個別の操作が必要です（一括で反映する仕組みはありません）。

1. 各子機で 設定 → 共有・ネット を開く
2. 親機のIPアドレスを新親機のもの（手順4-3でメモしたもの）に変更して保存
3. アプリを再起動
4. 「接続テスト」ボタンで疎通を確認

## バックアップ方式の選び方

| 方式 | APIトークン | 患者情報 | 用途 |
|---|---|---|---|
| 暗号化（パスワード） | 引き継がれる | 含む | **親機の機種変更（本手順）はこちら** |
| 匿名化（平文） | 除外される | 除外される | 分析・サポート提供用 |

暗号化バックアップは`safeStorage`（OS資格情報）に依存しない独立方式のため、
別PCへの復元でも問題なく動作します。

**APIトークンに関する注意:** 暗号化バックアップを復元した場合、旧親機と
同じAPIトークンが引き継がれるため、既にトークンを設定済みの子機は
**手順6（IPアドレス変更）だけで再接続できます**。一方、新親機を復元せず
初期設定ウィザードからゼロで作った場合は新しいトークンが自動生成されるため、
すべての子機でAPIトークンの再入力も必要になります。

## チェックリスト

- [ ] 旧親機で暗号化バックアップを取得した
- [ ] 新親機でバックアップを復元した
- [ ] 新親機で「親機として動作する」を選択・保存し、再起動した
- [ ] 新親機のIPアドレスをメモした
- [ ] 旧親機を電源オフ、または子機モードに切り替えた
- [ ] すべての子機のIPアドレス設定を新親機に変更し、再起動した
- [ ] 各子機で接続テストが成功することを確認した

## Electron 1.x → Go / Wails 2.0

1. Electron版で通常バックアップと、必要に応じてパスワード暗号化バックアップを取得する。
2. Go版を同じWindowsユーザーで起動し、`db.json.pre-go-migration` が作成されることを確認する。
3. Go版が既存 `db.json` を読み込み、旧 `DEPART_REGISTERED` を `MOVING` へ変換することを確認する。
4. Electron safeStorage形式の復号に失敗した場合は、元のDBを削除・上書きせず、Electron版で平文またはパスワードバックアップを作成してから再試行する。
5. バックアップ復元後は、患者登録、移送状態遷移、親子通信、CSV、WebRTCを回帰確認する。

Go版は暗号化・移行に失敗したデータを自動的に破棄しません。復旧できない暗号文を検出した場合は、診断情報に秘密情報を含めず、復旧手順だけを表示します。
